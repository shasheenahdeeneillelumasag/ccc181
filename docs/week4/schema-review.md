# Schema self-review

1. **Works well:** Every requirement with Stores data? = Yes has a table or column in schema.md (2a): FR-01 to FR-07, FR-10, and FR-13 are covered, FR-12 is marked Later, and FR-08 and FR-11 were dropped. The family tasks (join, see my place) and the staff tasks (call the next family, mark received) all have the data they need. **Problem (question 1):** `tickets.called_at` is a column that no requirement needs. FR-04 only needs the status to change to "called". No requirement says to save the time when the family was called. **Change:** I kept it. It has a check so it can't be before `created_at`, and it can show how long a family waited after being called. I wrote this reason in schema.md (2c).

2. **Works well:** Both foreign keys use RESTRICT, so deleting a barangay or a family never removes the ticket history. **Problem (question 2):** A family whose last ticket is no longer open (no-show or left) can join again. If Flask saved them as a new family, the same facts (name, size, barangay) would be in two rows. **Change:** I wrote in schema.md 2c notes that it finds the family that is already saved by `(barangay_id, head_name)` and only adds a new ticket.

3. **Works well:** `tickets.id` is made by the database, so two families can never get the same ticket number. **Problem (question 4):** Nothing stopped one family from getting two rows in families. **Change:** I added `UNIQUE (barangay_id, head_name)` in schema.md (2c). To make clashes rare, the form will ask for the full name and use the same capitalization.

4. **Works well:** I don't store the position in line. It is computed from `created_at`, `status`, and `household_size`, so nothing needs updating when a family joins or leaves. **Problem (question 4):** A family that already received goods could join the queue again. The database only stops it at the end, when staff mark the second ticket as received which is too late. **Change:** I kept the partial unique rule. I also wrote in schema.md that this database covers one distribution, and that Flask will check at joining time if the family already received.
